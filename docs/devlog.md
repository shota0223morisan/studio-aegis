## 2026-10-02 — 仕様書から最初の版を作る

**やったこと**
- 仕様書を渡して作ってもらった。仕様書の最終ゴールは「DAW と Studio Aegis の 2 つだけ開いていればいい」個人用の音楽制作ハブ
- 案件一覧と案件ページを作った。案件ページには Spotify のリファレンス再生、Splice の Stack リンク、構成メモ(Markdown)、箇条書きのアイデアメモ、音源ファイルのアップロード(先方リファレンス/完成版/その他)がある
- 中身は Express + SQLite のサーバーと React の画面。Docker で自宅サーバーに置く想定だった

**詰まったこと・原因**
- Splice をアプリ内に埋め込めなかった。splice.com は他サイトへの埋め込みを拒否する設定(`X-Frame-Options: SAMEORIGIN` / `frame-ancestors 'self'`)で、埋め込み用の公開 API もない
- Spotify 連携は、本物のアカウントで試せていなかった。ダミー ID で認証画面に移るところまでしか確認していない

**どう解決したか**
- Splice は「新しいタブか横に並べた別ウィンドウで開く」にした。のちに Mac アプリ化したことで、アプリ内表示が実現する(後述)

**思ったより簡単/難しかった点**
- 会話ログでは、仕様書を貼ってから最初のコミットまで約 15 分(時刻から計算)
- 「Splice をアプリ内に表示」は、Web アプリでは仕組み上できなかった

**非エンジニア目線で面白いポイント**
- 「サイトの中に別のサイトを表示する」は、表示される側(Splice)が許可していないとできない。ブラウザのルールで決まっている

## 2026-10-02 — 「常時起動マシンは使いたくない」→ Cloudflare に引っ越し

**やったこと**
- 自宅サーバー前提をやめて、Cloudflare(Workers + D1 + R2)で動く形に作り直した
- 大きな WAV に対応するため、20MB ずつ分けてアップロードするようにした
- パスワード未設定のまま公開されたら、自動で停止する安全策を入れた
- セットアップ用スクリプトを作り、本人の Mac のターミナルで実行してもらった

**詰まったこと・原因**
- Mac で `npm: command not found`。Node.js が入っていなかった
- デプロイ途中で止まった。Cloudflare が「workers.dev のサブドメインを登録しますか?」と聞いてきたのに、スクリプトが答えを入力できない形で動かしていたため、自動で「no」になった
- 確認の「Ok to proceed?」で Enter だけ押すと、既定の「no」が選ばれて止まった
- パスワードを何も入れずに Enter を押してしまった
- データベース ID が本人の手元のファイルにしか書き込まれず、GitHub 側は空のままだった

**どう解決したか**
- Node.js のインストール手順を案内した
- サブドメインの質問に答えられるようにスクリプトを直した。その場は `wrangler deploy` を直接実行してもらった
- パスワード未設定のときは停止する作りだったので、危険な状態にはなっていなかった。`wrangler secret put` で入れ直した
- データベース ID を GitHub 側にも書き込み、Cloudflare の自動デプロイ(Workers Builds)をつないだ

**思ったより簡単/難しかった点**
- 難しかった: ターミナルでの手作業が多く、何度もやり取りが必要だった。本人からも「Lyric Machine より面倒なのはなぜ?」と質問が出た
- 理由として挙げたのは、大きな音源ファイルの保存、複数端末での同期、ネットに置くためのパスワードの 3 つ

**非エンジニア目線で面白いポイント**
- ターミナルの「Enter だけ押すと no」の罠。質問の既定の答えは、大文字で書かれた側だったりする
- 「スマホから見られる」「どこでも同期」を求めると、とたんにサーバー・データベース・パスワードが必要になる

## 2026-10-02 — Mac アプリ化、そして「Mac 完結版」へ方針転換(v0.1.0 → v0.2.0)

**やったこと**
- v0.1.0: Electron で Mac アプリ(.dmg)を作った。最初は Cloudflare 上のアプリを表示する殻だった
  - Mac アプリなら Splice を窓の横のパネルに表示できた(Web では無理だったもの)
  - GitHub Actions で Apple Silicon 版と Intel 版の dmg をビルドして公開する仕組みを作った
- 本人の条件を確認した:
  - 「音源は 1 曲あたり多くても mp3 が 5 曲くらい」
  - 「自分の PC で見られればよく、スマホからは不要」
- v0.2.0: その条件を受けて「Mac 完結版」に作り直した。データは Mac の中(SQLite とファイル)に置き、アカウント・パスワード・デプロイは不要になった

**詰まったこと・原因**
- 本人は最初からデスクトップアプリとしてダウンロードするつもりだった(「これはデスクトップアプリでダウンロードするつもりだったが」)。Web アプリ前提で進めていたのとずれていた
- アプリ内の Electron ブラウザには Spotify の再生に必要な DRM(Widevine)が入っていない。そのため Spotify のフル再生は Spotify アプリ側で鳴らす形にした

**どう解決したか**
- 利用条件(1 台の Mac、ファイル少なめ)を聞いたうえで、Cloudflare をやめて Mac 完結にした。手間がほぼなくなった

**思ったより簡単/難しかった点**
- 結果的に、Cloudflare の設定に使った時間は Mac 完結版への転換で不要になった
- 最初に使い方(誰が・どの端末で・どれくらいのデータを)を確認していれば避けられた遠回り

**非エンジニア目線で面白いポイント**
- 「Web では埋め込めない Splice」が「Mac アプリなら表示できる」。アプリの中の窓は、ブラウザのタブと同じ「一人前のページ」扱いになるため
- 要件を少し削る(スマホ不要)だけで、構成がぐっとシンプルになった

## 2026-10-03 — 書くのが面倒問題:「書く or チェック」で進める(v0.8.0)

**やったこと**
- 本人の問題提起: 「コードとか書かないと進めないのは面倒。DAW にも打ち込むわけで本末転倒。ただ書いたら書いたでメリットも欲しい」。まずアイデアを出し、全部採用になった
- どのクリア条件も、アプリに書くか、チェックを入れる(DAW で決めた)かのどちらかで満たせるようにした
- コード進行の一言入力を作った。例: `4536`、`453メジャー6`、`6フラット7フラット1`、ローマ数字、コード名、`サビ 4536 A: 1645` のようなセクションごとの指定。基本はダイアトニック
- 書くと得する機能:
  - コード進行から、ベース・ピアノ・ストリングス・アルペジオの MIDI をワンクリックで生成
  - 参考曲のテンポと並べて比較
- 曲まるごとの MIDI を読み込むと、トラック名から楽器を判別して MIDI 倉庫へ分けて入れる。テンポ・キー・コードなども自動で埋める
- AI の MIDI 生成で、参考 MIDI(ドラムのノート割り当てなど)を踏襲できるようにした。手早いヒューマナイズも付けた
- 細かい解説文を減らした
- JPOP テーマを 2 つに分けた。明るく爽やかな J-POP FRESH と、オシャレしっとり系の J-POP MELLOW

**詰まったこと・原因**
- コードの一言入力で、`3m7` や `2m7` が「3 つの度数を続けて書いたもの」と誤って分解された
- テスト用に作った MIDI ファイルのベースがずれていて、sus4 と判定された。判定のほうは正しかった

**どう解決したか**
- 「スペース区切りの中では、度数が 3 つ以上並んだときだけ続け書きとみなす」ルールにした
- テスト用ファイルのほうを直した

**思ったより簡単/難しかった点**
- 難しかった: 音楽の書き方の「ゆれ」を全部受け止めること(`453メジャー6` と `6フラット7フラット1` が混ざるなど)

**非エンジニア目線で面白いポイント**
- 入力の手間を増やさず、「書いたら MIDI が出てくる」というご褒美で書く理由を作った

- v0.9.0 で起動直後に落ちるようになった。Dock などに出す内部の名前(CFBundleName)まで Session Partner に変えたため、起動時にアプリが「Session Partner Helper」という部品を探すようになった。実際の部品は「Studio Aegis Helper」のままで、見つからずに落ちていた

- v0.10.0 の自動テストで失敗: ファイル名を変えたあと、アプリの再起動機能が古いファイルの場所から起動しようとして失敗した(`base::LaunchProcess failed`)

- 内部の名前を戻して v0.9.2 を出した。アプリが起動しないので自動更新は使えず、一度だけ dmg から入れ直してもらった

  - データの保存場所は旧名のまま固定し、曲・メモ・ログイン状態を引き継いだ
  - 旧名で入っているアプリは、初回起動時に自分のファイル名を変えて開き直す
- 再起動は、アプリが終了するのを待ってから新しい名前のアプリを開く方式に変えた

**思ったより簡単/難しかった点**
- 思ったより難しかった: 「アプリ名を変える」。表示名・ファイル名・内部の部品名・データの保存場所・自動更新がつながっていて、1 か所だけ変えると壊れる

**非エンジニア目線で面白いポイント**

## 2026-10-07 — 明るいテーマ 3 種と「ドーパミンが出る」デザイン(v0.11.0)

**やったこと**
- 明るいテーマを 3 つ追加した: ORGANIC(草・葉っぱ)、SKY(雲・波)、NOTEBOOK(罫線・マスキングテープ)
- 本人の希望: 「もっと大げさに、ドーパミン出る感じで」。全 11 テーマに、それぞれの世界観のイラストを背景と曲ページ上部に入れた
  - 例: ROCK はスポットライトと観客、ELECTRO はレーザーとミラーボール、SKY は海とヨット
- 動きを足した:
  - 今のステージが脈打つ、光が走る、カードが浮く
  - ステージを進めると紙吹雪、提出で大きな紙吹雪
  - チェックでキラッと光る
- ELECTRO を 2 回調整した(下記)

**詰まったこと・原因**
- チェックを入れた行に、どのテーマでも緑の枠が出ていた。チェック行に付けた名前(`auto`)が、BPM の「AUTO」バッジ用の見た目と同じ名前でぶつかっていた
- 新テーマのステージ色が効かなかった。別のファイルの指定のほうが優先されていた
- ELECTRO の指示の行き違い: 「ミラーボールのはそこまで透過しなくていい」を、背景を濃くすることだと受け取った。実際の意図は「文字や枠に被る部分の透けを減らして見やすく」だった

**どう解決したか**
- 名前を `is-auto` に変えて、ぶつからないようにした
- 指定の優先度を上げた
- ELECTRO はカード・バー・サイドバーをほぼ不透明にした。まだ進めないステージのタイルは、タイルごと半透明だったのを文字だけ薄くする形にした

**思ったより簡単/難しかった点**
- イラストは画像を描いたのではなく、プログラムで図形を組み合わせて作った(SVG を生成するスクリプト)
- 難しかった: 「派手さ」と「読みやすさ」の両立。背景が見えるのはカードの外側だけにして、作業中の文字の見やすさは保った

**非エンジニア目線で面白いポイント**
- 「透過しなくていい」という同じ言葉でも、背景のことか、文字の下のことかで正反対の直し方になる
- デザインを変えるときは、毎回スクショで見てから公開する流れが定着した

## 2026-10-07 — 自分用メモを「どこでも出せる窓」に。広い画面の最適化(v0.12.0)

**やったこと**
- 広い画面(FOCUS など)では曲ページも横に広げた。参考曲の枠は最大で横 3 つ並ぶ
- 自分用メモを、ページのスクロールから切り離した:
  - 広い画面では右に固定し、左端をドラッグで幅を変えられる
  - ✕ でポップアップになり、⇥ で右に戻る
  - ポップアップは左上の角をドラッグで大きさを変えられる
  - ⌄ でしまうと右下のボタンになる
- 曲以外のページでは、どの曲にも属さない「ひらめきメモ」を出す
- メモは最初ステージごとに分けたが、本人の判断で「曲に 1 つ」にした。前のステージ別メモは、見出し付きで合流させた
- AI は曲のメモを読むようにした

**詰まったこと・原因**
- 「全ページ共通」「全窓の時は右側に固定」の意味が、いくつかに取れた
  - 「全ページ共通」: メモの中身が共通なのか、メモの出る場所が共通なのか
  - 「全窓」: 3 窓のときなのか、アプリが全面のときなのか
- 試作で広い/狭いを切り替える基準は、画面の幅(1480px)にした。そのため「FOCUS のときだけ固定」とは完全には一致しない(大きいモニターなら窓を開いていても固定になる)

**どう解決したか**
- 先に試作とスクショを出して、本人に選んでもらった。そこで次の 2 点が決まった:
  - 「ポップアップは手動で大きさ変更、FOCUS は基本右、✕ でポップアップに」
  - 「ステージ分けは不要、曲に一つ」

**思ったより簡単/難しかった点**
- 言葉だけの要望を形にするより、「まず試作を見せて決めてもらう」ほうが早かった

**非エンジニア目線で面白いポイント**
- 同じメモ欄でも、画面の広さで「横に固定」「浮かぶ小窓」「しまったボタン」の 3 つの姿に変わる
